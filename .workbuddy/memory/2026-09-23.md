## TTS 选型事实 + 「离线语音包」可行性测算（用户提问）

- 当前 TTS 配置（`preset_config.json`）：`stepaudio-2.5-tts` / voice `jilingshaonv` /
  `https://api.stepfun.com/step_plan/v1`，走 **非流式** `POST /audio/speech`。
  英语不走云端（系统 TTS），所以下面只算日语。
- **模型档次**：stepaudio-2.5-tts 是旗舰「语境 TTS」（双档语境控制/3 秒复刻/300+ 音色，
  曾进 Artificial Analysis Speech Arena 全球前三）；`step-tts-2` 官方写明是
  「step-tts-mini 的升级版」。→ **换 step-tts-mini 是降级，别换。**
- **慢不是模型慢**：2.5-tts 官方口径流式延迟 <200ms；我们实测 1.2–2.4s 且与文本长度无关，
  是因为用了非流式端点、等整段合成完。stepaudio-2.5-tts 另提供 **WebSocket 流式合成**端点 ——
  **真正的提速点是换流式端点，不是换更弱的模型**。（用户本次选择「先不动」）
- **词库规模实测**：assets 合计 47,876 条；其中日语 ja_n1 3463 / n2 1793 / n3 1784 /
  n4 632 / n5 662 / kana 46 / n5_vocab 138（≈8.5k，n5_vocab 可能与 ja_n5 重叠）。
- **全量预加载不可行**：日语 ≈8.5k 词条 × 2（词+例句）≈ 1.7 万条音频，
  按实测均值约 26KB/条 → **≈440MB**；并发 2、1.7s/条 → **≈4 小时**；
  按 5.8 元/万字符公开价粗估 **≈150–190 元**。
- **可行的粒度**：只做 N5（662+46 假名）≈ 708 词条 → 1416 条 ≈ **37MB / 约 20 分钟 / 约 15 元**，
  刚好塞进现有 64MB 缓存。N5+N4 会到 ~70MB，超过 64MB 上限。
- ⚠️ 若要真做「离线语音包」，**不能放 cacheDir**：系统存储紧张时会清、设置里「清除缓存」也会清，
  且 64MB LRU 会悄悄淘汰。应放 `filesDir`（如 `files/offline_tts`）并独立于 LRU 管理。
- **离线语音包的备选方案（按性价比排序）**：
  1. 「今日队列 + 未来 N 天复习队列」全预取 + 把学过/待复习的词 pin 住不淘汰 ——
     量级仅几十~几百条（1–5MB），日常 100% 秒响、断网时学过的都能响，**零下载、零包体代价**，最划算；
  2. 按等级下载到 filesDir（N5 ≈37MB / 20 分钟）；
  3. 内置 assets 只放极小核心（假名 46 + N5 基础 138 ≈ 4.8MB），装上即有，APK +5MB；
  4. 格式瘦身：`OpenAiWire.buildTtsBody` 里 `response_format` 现在**硬编码 mp3**，
     若 stepfun 支持 opus，体积可望减半（上面所有数字 ×0.5）—— 值得先试。
  5. 系统 TTS 离线语音包：国内机型不可靠（§17.16 就是因此改走云端），不推荐。
- **回合制录音链路**（本次未验、风险最高的未覆盖路径）：
  **场景对话页点「录音」（`chat_record`）开始、再点「停止」（`chat_stop`）结束**
  （`ChatActivity.toggleRecording()`，L127 `setOnClickListener`）→ `AudioRecord`
  → `AudioVadTrimmer.trim`（阈值 -45dBFS）→ `POST /audio/transcriptions` → 回填输入框。
  只有单测（喂合成 PCM），真机从未跑过。最可能翻车的是 **-45dBFS 对真机麦克风电平不合适**
  → 整段被判静音裁光 → 上传空音频 → 识别结果为空。
