## ★ 已完成 B′：实时语音的用户字幕改用独立识别（v1.0.7）

**思路**：既然实测证明「stepfun 实时通道听得懂日语、错的只是那行字幕」（§17.21.3），
就不必换模型或加第二条 WebSocket —— 把字幕这一路单独修好即可。

**链路**：`onAudioFrame` 一帧两用（照旧 sendAudio + 另存副本）→
`onUserTranscript` 先显示占位「识别中…」→ drain + `VadPolicy` 端上裁静音 →
包 WAV → 送 `SttProviders` 识别 → 成功覆盖气泡并同步改 `recordedTurns[turnIndex]`；
失败/空**一律回退到实时通道给的原文本**（绝不留占位卡住）。

**触发条件（不满足则零回归）**：
- 新增 `LangId.realtimeTranscriptReliable`：**日语 false、英语 true**
  （实时通道对中英是准的，英语不必多花一次请求）
- 且语音识别组已配置

**新增件**：
- `core/audio/WavWriter.kt`（裸 PCM→WAV；`ProbeAudio` 改为委托它，消除重复头部写法）
- `core/audio/Pcm16.kt`（小端字节↔样本；`VadPolicy` 吃 ShortArray、采集给 ByteArray）
- `core/audio/PcmUtteranceBuffer.kt`（累积一句音频，**30 秒上限**防失控）
- `core/audio/RealtimeTranscriptAudioTest.kt`（14 例）
- 字符串 `voice_transcript_pending`；日志标签 **`ShiyuStt`**
  （SEND / CORRECTED / EMPTY / FAIL / SKIP + 耗时，便于真机验证）

**几个刻意的决定**：
1. WAV 头必须写真实采样率 **24000**（复用 `RealtimeAudioController.SAMPLE_RATE`）
2. 临时文件名**带纳秒** —— 连续两句识别可能重叠，共用名字会互相删文件
3. 端上先裁静音再上传：省计费，且纯静音会被服务端判空转写、白花一次请求

**待验证**：真机说日语应看到「识别中…」→ 正确日文；`ShiyuStt` 应出现 SEND + CORRECTED。
英语与「识别组未配置」两种情况都不受影响。

## ★★ 对照实验定论：stepfun ASR 救不了，Whisper 一次就对（v1.0.9）

用户反馈「没啥用啊」后逐层排查，最后拿**真实录音**做对照实验，结论明确。

**排查过程（每一步都有证据，避免靠猜）：**
1. `纠错开关=true（语言=ja 实时转写可信=false 识别组可用=true）` → 功能确实启用了
   （之前先后误怀疑过配置和版本，所以这条日志是**无条件打印**的，值得保留）
2. 发现真实缺陷：实时链路**关麦时会推等长静音帧**，被我一起缓冲 →
   `VadPolicy` 看到「大段全零+小段人声」，易超 `maxTrimmedRatio(0.98)` 被判无语音 →
   **直接放弃纠错**，表现成"功能没生效"。修：只在 `audio.pushing==true` 时缓冲；
   且裁不出语音也**不 return**，改送整段。→ v1.0.8
3. 修完仍不对：日志显示 `原文='哦，还有个人也冇睡。'` / `纠错='哦，还有个大姨妈事。'`
   —— **两者不同**，证明纠错链路跑通了，但**识别输出也是中文**。

**根因（实测确立）：`language` 只是软提示，实际由自动语种检测决定。**
用户说「おはようございます」，两条链路都给出**忠实的中文谐音**：
- 实时通道：`哦，还有个人也冇睡。` ≈ o-ha-yo-u / go-za-i-ma-su
- 独立识别：`哦，还有个大姨妈事。` ≈ o-ha-yo-u / go-za-i-ma-su

**这同时修正了 §17.21.4 的一个误读**：当初用「中文音频 + language=ja → 返回『你好』」
当作"请求格式正确"的证据，其实那条恰恰证明 `language` **不被强制**。
而原生发音样本会正确判成 ja，所以这个坑**只在学习者口音下暴露** —— 我用原生样本测通了就下结论，是样本选错。

**取证手段（可复用）**：`DEBUG_DUMP_UTTERANCE`（`VoiceChatActivity` 内临时开关）
把每句送去识别的音频覆盖写到 `Android/data/com.shiyu.app/files/stt_debug/last.wav`，
**该路径实测可用 `adb pull` 取出**（`/sdcard/Android/data/` 在本机可读）。
样本留存：`.workbuddy/user_utt.wav`（177KB / 3.7s / 24kHz，已 gitignore）。

**实验一：stepfun ASR 6 种组合全失败**（同一段录音）
language=ja / +prompt / +强prompt / +hotwords / +prompt+hotwords / language=zh
→ 输出**始终中文**；`prompt`/`hotwords` 会改变结果（6 组出 4 种文本）但改不了语种；
`language=ja` 与 `language=zh` 落在同一结果 → **证实 language 不参与强制**。

**实验二：Whisper（faster-whisper small / CPU / int8）一次就对**
- `language=ja` → ja(1.00) → **`おはようございます`**
- 自动检测 → ja(0.80) → **`おはようございます`**
→ 用户发音**清楚可识别**，问题完全在 stepfun 侧。耗时约 2.25s（1.65× 实时）。

**推荐**：
- **A（推荐，零代码改动）**：ASR 组指向 Whisper 兼容服务（Groq `whisper-large-v3` 免费额度 /
  OpenAI `whisper-1` / 自建 faster-whisper）。工程已支持该协议，**设置页填三个框即可**。
- **B（免费/先验证）**：本机搭 OpenAI 兼容 Whisper 端点，手机走局域网指过来。
- **C（兜底）**：日语实时语音下不显示用户字幕（不显示优于显示错误内容）。

**环境踩坑**：Windows 上 huggingface_hub 无符号链接权限（未开开发者模式）时，
`snapshots/` 下会建成 **0 字节空文件**，报
`File model.bin is incomplete: failed to read a value of size 4 at position 0`；
`blobs/` 里其实是完整的 → **手动把 blob 复制成 snapshot 里的文件名**即可解决。

## ★★ 定稿方案：日语语音转写走火山方舟（v1.0.10 / v1.0.11）

**用户产品决策**：英语保持原通路（stepfun 实时通道自己的转写），
**只有日语语音转文字走火山通路**，其他不动。

### 为什么最终选火山

| 方案 | 结论 |
|---|---|
| stepfun ASR | ❌ 实测 6 种参数组合全输出中文，`language` 不参与强制（§17.21.10） |
| 硅基流动 SenseVoice | 未测（零代码，但没继续验证） |
| 本机 Whisper | ✅ 效果全对，但 `BaseUrlNormalizer` 只允许 https/wss，本机 http 端点走不通 |
| **火山方舟 + 豆包** | ✅ **选定** —— 大模型可用指令指定输出文字体系 |

### 火山这条路的关键实测（缺一个就废）

1. **必须关思考模式** `thinking:{type:"disabled"}`：
   开着同一段音频 **36~137 秒**，关掉 **1~3 秒**。这是能用于字幕的前提。
2. **提示词必须指定输出文字体系 + 禁止解释**：
   只说"逐字转写" → 中文谐音 `哦哈哟够咱一妈塞`；
   不禁止解释 → 一大段说明文字，还慢几十秒。
3. **上传后无需等文件处理**（status=processing 也能用）：上传 305ms + 转写 1701ms ≈ **端到端 2 秒**。
4. **用完必须删文件**：每句话都上传，`DELETE /files/{id}` 实测可用，失败不影响转写。
5. 模型：`doubao-seed-2-0-mini-260428`（实测最快 1.1s）。
   另两个可用：`doubao-seed-2-0-lite-260428`、`doubao-seed-2-1-lite-260915`。

### 代码结构

- `core/net/ArkAsrWire.kt`（纯 JVM 协议层）+ `ai/openai/ArkSttProvider.kt`
- `ai/SttContract.kt`：`EMPTY_TRANSCRIPT` 公共常量（三套 Provider + 设置页探活共用）
- `SttProviders`：**三套协议按 host 择一**（唯一判断点）
  - `*.volces.com` → 方舟两步
  - `*.stepfun.com` → `/audio/asr/sse`
  - 其它 → Whisper 兼容 `/audio/transcriptions`
