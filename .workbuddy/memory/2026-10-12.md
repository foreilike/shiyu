# 2026-10-12

## ★ 实时语音改为「自由聊天」——修「每次都问名字」的死板问题（v1.0.13）

**用户反馈**：实时对话时英语过于死板、**每次都问名字**，日语也相对死板；
想要**随机的、自然的对话**。问我「是不是我们加了约束」——**是的，两处叠加**。

### 根因（缺一个都不会这么明显）

**① 结构性问题：实时语音永远进「自我介绍」场景**
两个入口都写死 `scenarios.first()`：
- `HomeActivity.openVoice()`（首页 REALTIME TALK 卡片）
- `ChatListActivity` 的 `btnVoiceRealtime`（对话页顶部同一入口）

而 `scenarios_en.json` / `scenarios_ja.json` 的**第一个场景都是 `self_intro`**。
且**实时页标题只显示「AI 语伴 · 日语」，不显示场景** → 用户无从察觉。

**② 提示词里的强约束（自己加的）**
`VoicePrompts.forScenario()` 末尾：「这个场景可以引导对方说出这些表达：…
**自然地创造机会让他说出来**」。而 self_intro 的 `goalExpressions`
第一条就是 `My name is ...` → 开口就问名字；只有 5 条，问完就重复 → 像问卷。

**佐证**：2026-09-28 真机两次会话开场**都是「おはようございます！…」**
（`今日はどうしましたか？` / `元気でしたか？`）—— 同场景固定的重复特征。

### 修法（用户选定）

| 决策 | 内容 |
|---|---|
| 实时语音默认 | **自由聊天**（不绑场景） |
| 场景引导提示词 | **完全去掉** |

### 改动

- `VoicePrompts`：**删** `forScenario()`（改完无人调用）；**新增** `forFreeTalk()` +
  `freeTalkHints()`
- 自由聊天提示词的关键新约束（只写"要自然"不够，必须**点名坏行为**）：
  - 「话题跟着对方走，并且要经常换」+ 给了具体话题方向
  - 「**严禁反复提问同一个问题**」，并点名「你叫什么名字/你从哪里来/你几岁」
    + 一句判断「那是问卷，不是聊天」
- `VoiceChatActivity`：去掉 `scenario` 字段与场景查找；`intent()` 不再要 scenarioId；
  落盘用保留 id `free_talk` + 中文标题；副标题显示语言+模式
- `HomeActivity` / `ChatListActivity`：去掉 `scenarios.first()` 这个 hack
- `SessionStore.saveRealtimeSession` 增加 `title` 参数
- 「提示」按钮改为**随机话题方向**（原来给的是场景目标表达）
- 新增 `VoicePromptsTest` 12 例

### 真机验证（v1.0.13）

- 副标题显示 **「AI 语伴 · 英语 · 自由聊天」** ✓
- 从 `session.updated` 抓到实际发出的 instructions：**新提示词已生效，
  场景引导段（"自然地创造机会让他说出来"）已消失** ✓

### 副作用（是好事）

自由聊天落盘用保留 id `free_talk` → 「对话」页按 `scenarioId` 分组统计场景轮数时，
**自由聊天的轮数不会再被算进「自我介绍」**。

### 教训

这次是**两处独立的小决定叠加**造成的用户可见问题 ——
「实时语音随便找个场景提供 prompt」+「提示词引导学习者说出目标表达」，
单看都合理，合起来就是"每次都被问名字"。
**加约束时要问一句：这个约束在真实使用频率下会退化成什么？**
