# 拾语 · 日语词库中文翻译 PRD

> 目的：为拾语 App 的日语词库（JLPT N5–N1，共 **8334** 词）补齐**中文释义**和**例句中文译文**。
> 词库、假名、罗马音、日文例句都已就绪，**只缺中文**。这份文档交给翻译模型执行，产出回收后由拾语按 id 合并入库。

---

## 1. 背景（给模型的上下文）

- 拾语是一个面向**中文母语者**的日语学习 App，卡片形式：正面给词+释义，翻面给假名读音+例句。
- 词库来自开放数据集 OpenJLPT（日→英），所以每个词只有**英文释义**和**英文例句译文**，没有中文。
- 你的任务：为每个词产出**简体中文释义**（`meaningZh`）和**该词日文例句的简体中文译文**（`exampleZh`）。

## 2. 输入文件

位置：`docs/ja-translation/input/` 下 5 个文件，按 JLPT 级别拆分：

| 文件 | 级别 | 条目数 |
|---|---|---|
| `ja_n5.json` | N5（入门） | 662 |
| `ja_n4.json` | N4（初级） | 632 |
| `ja_n3.json` | N3（中级） | 1784 |
| `ja_n2.json` | N2（中高级） | 1793 |
| `ja_n1.json` | N1（高级） | 3463 |

每个文件是一个 JSON 数组，元素结构：

```json
{
  "id": "n5_0001",
  "word": "あさって",
  "kana": "あさって",
  "romaji": "asatte",
  "meaningEn": "day after tomorrow",
  "exampleJa": "あさって来てください。",
  "exampleEn": "Come the day after tomorrow."
}
```

- `word` 是展示词（有汉字给汉字，否则给假名）；`kana` 是读音；`meaningEn` 可能是分号分隔的多个义项。
- `exampleJa` 可能为空字符串（该词无例句）。

## 3. 输出契约（**必须严格遵守**）

对每个输入条目，输出一个对象，**只含三个字段**：

```json
{ "id": "n5_0001", "meaningZh": "后天", "exampleZh": "请后天来。" }
```

硬性要求：
1. **`id` 原样保留**，不得改动、不得新造 —— 合并时按 id 对齐。
2. **一进一出、数量相等、顺序不变**：输入 N 条就输出 N 条，不合并、不遗漏、不新增。
3. 输出是**一个 JSON 数组**，可直接被 `json.parse` 解析（不要包裹 markdown 代码块以外的解释文字）。
4. `exampleJa` 为空 → `exampleZh` 也给空字符串 `""`（不要编造例句）。
5. 只输出 `id / meaningZh / exampleZh` 三个字段，**不要**回带 `word/kana/meaningEn` 等原字段。

## 4. 质量标准

### meaningZh（中文释义）
- 面向中文学习者的**词典式简明释义**，通常 2–8 字；多义项用 `；` 分隔，最多保留 2–3 个常用义。
- 保留词性习惯（可选加「动」「名」「形」等，但不强制）。参照英文 `meaningEn` 但以日语词本义为准。
- ✅ `day after tomorrow` → `后天`
- ✅ `to bathe; to shower` → `淋浴；洗澡`
- ❌ 不要长句解释：`day after tomorrow` → ~~「指今天之后的第二天」~~

### exampleZh（例句译文）
- 翻译 `exampleJa`（日文原句），`exampleEn` 仅作参考。要**自然、口语、符合中文表达**，不是逐词硬译。
- 与该 JLPT 级别难度相称；保留原句语气（命令/疑问/陈述）。
- 人名（トム 等）按常见中文译名或音译（Tom→汤姆）；地名、专有名词用通行译名。
- ✅ `あさって来てください。` → `请后天来。`
- ✅ `あそこを見て。` → `看那边。`
- ❌ 不要把英文译过来当中文：以日文原句为准。

## 5. 分批与执行建议

- N1/N2/N3 文件较大，建议**每批 50–100 条**喂给模型，逐批产出后拼接。
- 每批把上面第 3、4 节的要求作为 system/前置指令固定带上。
- 可以多个模型/多人分工：按文件或按 id 区间切分，最后合并。
- 强模型（GPT-4o / Claude / DeepSeek-V3 等）质量更稳；4B 小模型不建议跑这个。

## 6. 交付前自检清单

- [ ] 每个文件输出条数 == 输入条数。
- [ ] 所有 `id` 与输入一一对应，无缺、无重、无错位（可用脚本比对 id 集合）。
- [ ] `meaningZh` 无空值（除非该词确实无义，罕见）。
- [ ] `exampleJa` 非空的条目，`exampleZh` 也非空；`exampleJa` 为空的，`exampleZh` 为 `""`。
- [ ] 随机抽 20 条人工核对：释义准确、例句通顺、无英文残留、无多余解释。
- [ ] 输出是合法 JSON 数组（`json.parse` 通过）。

## 7. 怎么把结果给我（拾语这边合并）

- 按级别产出 5 个结果文件：`ja_n5.out.json` … `ja_n1.out.json`（或合并成一个大数组也行，只要 id 齐全）。
- 每个是 `[{id, meaningZh, exampleZh}, ...]`。
- 把文件发回即可，我按 `id` 合并进 `ja_*.json`，补上 `meaningZh/exampleZh`，然后把对应级别注册进 App 的选书列表、构建装机。
- 先回哪几级我就先上哪几级（建议优先 N5→N4→N3）。
